# GPU 모델을 어디서 돌릴지 (Issue #11)

2026-11-25 결정.

## 상황

배포하려면 GPU가 필요한 모델 두 개를 돌릴 곳이 있어야 한다.

- PaddleOCR-VL-1.5: 사진에서 글자 읽기
- gemma4:e4b: 사진 결과 정리, 설명서 근거 읽기, 추천

지금은 둘 다 내 PC(학교 PC, RTX 4070 12GB)에서만 돈다. 모델은 이전에 비교를 마쳤고 gemma가 가장 나았으므로, 이번에는 모델이 아니라 장소만 정한다.

## 후보

| 후보 | 비용 (지인 사용 1주) | 특징 |
|---|---|---|
| A. 내 PC(학교 PC) | 0 (전기료) | 지금 구성 그대로. 측정한 숫자가 있음 |
| B. GPU 서버 시간 대여 | 계속 켜 두면 약 $57~150 | 사진 인식을 리눅스용으로 바꿔야 함 |
| C. 요청 때만 켜지는 GPU | 쓴 만큼 (사용량 예시: 1인 약 76초) | B와 같은 작업 + 한동안 안 쓰면 첫 요청에 모델 올리는 시간 |

측정 결과와 요금 출처: [docs/eval/gpu-location/](../eval/gpu-location/README.md)

## 고른 것

**12월(배포 → 지인 사용 → 측정)은 A. 학교 PC.**

확인한 조건:

- 학교 허가를 받았다 (2026-11-25).
- 12월 내내 켜 둘 수 있다.
- 외부 접속: 학교 네트워크에서 Cloudflare 임시 터널로 시험 페이지를 열었고, 와이파이를 끈 휴대폰(데이터)에서 열렸다 (2026-11-25). 앱 서버는 열지 않고 시험 페이지 한 장만 열었다.

## 이유

- 12월 내내 켜 둘 수 있고 비용이 없다.
- 속도와 동시 사용을 이미 쟀다. 사진 1장 약 6초, 약 하나 검사 약 24초.
- 지금 구성 그대로 돌릴 수 있다. 사진 인식을 리눅스 컨테이너로 바꾸는 일은 계획대로 M3의 docker compose 때 한다.

## 감수한 것

- 2027년 1월에 학교를 나가야 할 가능성이 커서, 그때 서비스가 끝난다. 그 뒤에도 링크를 살려 둘지(①의 "써 보기" 줄)는 계획 세션에서 정한다.
- GPU가 1개라 요청을 한 번에 하나씩 처리한다. 3명이 동시에 검사하면 마지막 사람은 1분 넘게 기다린다.
- 정전이 되거나 인터넷이 끊기면 서비스가 멈춘다.
- 로그인을 넣으면 지인들의 약 목록(건강 정보)이 학교 PC에 저장된다. 학교를 나가기 전에 지워야 한다.
- 임시 터널 주소는 켤 때마다 바뀐다. 앱에 서버 주소가 들어가므로 실제 배포에는 고정 주소가 필요하다. 터널 방식은 M1 배포 때 정한다.
