# GPU 모델 속도·동시 사용 측정 (Issue #11)

2026-11-25 측정. GPU가 필요한 모델을 어디서 돌릴지 정하기 위한 기준 숫자다.

## 무엇을 쟀나

| 모델 | 하는 일 | 돌리는 방법 |
|---|---|---|
| PaddleOCR-VL-1.5 (GGUF) | 사진에서 글자 읽기 | `llama-server.exe` (포트 8090) |
| gemma4:e4b | 사진 결과를 '이름: 함량'으로 정리, 설명서 근거 읽기, 추천 | Ollama 0.40.18 |

- 장소: A 후보(내 PC). RTX 4070 12GB, Windows 11.
- AI 서버(`localhost:8000`)에 직접 요청했다. 백엔드 캐시를 거치지 않으므로 매번 모델이 실제로 돈 시간이다.
- 입력
  - 사진: 영양제 성분표 사진 11장 (`test_image/`, 저장소에 올리지 않음)
  - 근거 읽기: 근거 읽기 저장소(`evidence_reading_cache`)에 있는 실제 설명서 문장 36개(성분 짝 50개)를 3문장씩 묶은 12건. 약 하나 검사 = 1건
  - 추천: 약 1개 2건, 약 2개 1건
- 측정 전에 종류마다 준비 호출을 한 번씩 해서 모델을 메모리에 올렸다(첫 호출의 모델 올리는 시간 제외).

## 혼자 쓸 때

| 요청 | 건수 | 가운데값 | 범위 |
|---|---|---|---|
| 사진 1장 (성분이 나온 9장) | 9 | 5.7초 | 3.6~10.5초 |
| 사진 1장 (글자 반복으로 OCR 상한에 닿은 2장, 성분 0개) | 2 | — | 17.4초, 37.7초 |
| 근거 읽기 1건 (문장 3개, 성분 짝 3~6개) | 12 | 24.0초 | 15.7~36.7초 |
| 추천 1건 | 3 | 10.6초 | 9.8~12.8초 |

- 상호작용 검사 시간은 근거 문장이 있는 약의 수만큼 늘어난다. 백엔드가 약마다 1건씩 차례로 부르기 때문이다. 이미 읽은 문장은 저장소에서 꺼내므로 다시 부르지 않는다.
- 추천 3건 중 2건은 모델이 추천을 0개로 답했다(오류는 아님). 같은 입력(씬지로이드)이 준비 호출에서는 2개, 측정에서는 0개였다. 추천 품질은 Issue #12에서 따로 본다.

## 동시에 보낼 때

같은 순간에 여러 요청을 보내고, 각 요청이 끝난 시간을 쟀다. 2번씩 반복했다.

| 상황 | 1회차 끝난 시간 | 2회차 끝난 시간 |
|---|---|---|
| 사진 2장 | 2.8 / 8.9초 | 9.2 / 17.3초 |
| 사진 3장 | 5.1 / 13.0 / 15.6초 | 5.1 / 9.1 / 18.9초 |
| 근거 읽기 2건 | 40.7 / 56.9초 | 17.0 / 45.4초 |
| 근거 읽기 3건 | 16.7 / 45.3 / 62.3초 | 27.8 / 51.6 / 76.6초 |
| 사진 1장 + 근거 읽기 1건 | 둘 다 18.5초 | 둘 다 39.7초 |

읽는 법:

- **한 번에 하나씩 처리된다.** 끝난 시간이 계단처럼 늘어난다. 마지막 사람은 앞사람들의 시간을 모두 더한 만큼 기다린다. 근거 읽기 3건이 동시에 오면 마지막 사람은 약 1분~1분 15초를 기다렸다.
- **사진 인식이 AI 서버 전체를 잡고 있다.** 사진과 근거 읽기를 같이 보내면 둘이 꼭 같은 시간에 끝났다. 혼자면 3.6초 걸리던 사진이 근거 읽기와 겹치자 39.7초가 걸렸다.
  - 원인(코드 확인): 사진 입구 `/extract`는 `async def`인데 안에서 OCR과 gemma를 기다리는 동안 서버의 다른 일을 멈추는 방식으로 부른다. 반면 근거 읽기와 추천은 `def`라 따로 돈다.
  - 장소와 관계없이 생기는 문제라 이 시험의 결정과는 따로 고칠 일로 남긴다.
- gemma 하나를 세 가지 일(사진 정리, 근거 읽기, 추천)이 같이 쓰므로 사진 정리도 근거 읽기 뒤에 줄을 선다.

## GPU 메모리

- 두 모델을 다 올린 상태에서 최고 10,209MiB / 12,282MiB (Windows 화면 사용분 포함)
- 남는 자리가 약 2GB라 더 큰 모델이나 모델 하나 더는 올릴 수 없다.

## 후보 비교

A는 위에서 잰 숫자다. B·C는 가입하지 않아 재지 않았다. 요금은 2026-11-25에 찾은 공개 자료 기준이라 정할 때 다시 확인해야 한다.

| | A. 내 PC | B. GPU 서버 시간 대여 | C. 요청 때만 켜지는 GPU |
|---|---|---|---|
| 예 | 지금 PC (RTX 4070 12GB) | RunPod RTX 4090 | Modal L4 |
| 요금 | 추가 없음 (전기료) | 시간당 약 $0.34~0.89 | 시간당 약 $0.80, 실행한 초만 |
| 지인 사용 1주(12/14~12/20) 비용 | 0 | 계속 켜 두면 168시간 × 요금 = 약 $57~150 | 사용량에 따라 다름 (아래) |
| 속도 | 위 표 | 재지 않음 (GPU가 달라 다를 수 있음) | 재지 않음. 한동안 안 쓰면 첫 요청에 모델(약 11GB)을 올리는 시간이 붙음 |
| 동시 사용 | 한 번에 하나씩 (위 표) | A와 같음 (GPU 1개) | 요청이 몰리면 복사본을 더 띄울 수 있음. 복사본마다 첫 요청 지연과 요금이 붙음 |
| 해야 할 일 | 인터넷에서 접속할 수 있게 열기, 사용 기간 동안 PC 켜 두기 | 사진 인식을 리눅스용으로 바꾸기(지금은 Windows `llama-server.exe`와 Windows 절대 경로), 서버 이미지 만들기 | B와 같음 + 이 서비스 방식에 맞추기 |

C의 사용량 계산 예: 한 사람이 사진 3장 + 약 2개 검사 + 추천 1번을 하면 GPU 시간은 약 5.7×3 + 24×2 + 10.6 ≈ 76초다. 이 사용량은 예시일 뿐 실제 사용 횟수는 아직 모른다.

## 다시 재는 법

```powershell
# 1. 근거 읽기 입력 만들기 (근거 읽기 저장소의 문장을 문장별로 묶음)
docker exec pnn-postgres psql -U postgres -d pnn-db -At -c "select json_agg(t) from (select min(sentence) as sentence, json_agg(nutrient_group order by nutrient_group) as nutrients from evidence_reading_cache group by sentence_hash order by min(id)) t" > sentences.json

# 2. Ollama, AI 서버(8000)를 켠 뒤 측정 (약 15분)
ai-server\.venv\Scripts\python.exe docs\eval\gpu-location\measure.py --photos test_image --sentences sentences.json --out result.json
```

결과 JSON에는 걸린 시간·성공 여부·개수만 남고 사진·문장 내용은 남지 않는다.
